# Operating-system identity

The database authenticates the current process's OS identity. No database password is supplied. Supported adapters configure integrated authentication, existing Kerberos tickets or local peer authentication; see the driver prerequisites below.

**OLE DB is supported only on Windows.** All routes require a compatible provider or driver for the client OS and architecture.

## CLI and Library selection

Select --os-identity on connection check, schema deploy or schema inspect. It conflicts with password prompts, stored credentials, --username and OAuth; no password is acquired or retried.

The Library selects the same strategy with ConnectionAuthentication.OperatingSystemIdentity().

Support marks identify implemented driver mappings, not verified live authentication on every platform. Install the exact compatible driver and configure server accounts, TLS, SPNs and an existing ticket/session independently. No machine setup or ticket acquisition is performed.

- SQL Server ODBC requires Microsoft ODBC 17/18; OLE DB requires MSOLEDBSQL. LocalDB is Windows only.
- PostgreSQL supports network GSS/SSPI and separate local Unix peer authentication. psqlODBC requires libpq 16 or later. Self-hosted TimescaleDB and CockroachDB require their documented server configuration; CockroachDB GSSAPI requires Enterprise licensing.
- MariaDB and SingleStore require plugin-only server accounts and an explicit URL database-role hint. Native Linux Kerberos login and negative cases were verified on .NET 8/9/10. Other platforms and ODBC remain mapping evidence.
- MySQL requires explicitly selected MySql.Data or MySQL ODBC 8.0.32 or later and the Enterprise Kerberos server plugin. The default MySqlConnector/MySQL route is unsupported. Live MySQL acceptance is blocked by the unavailable licensed server.
- Db2 requires TargetPrincipal and the platform-specific IBM package. Oracle requires external-authentication/Oracle Net prerequisites. Teradata requires vendor SPNEGO support; Firebird trusted authentication is Windows only and does not establish Kerberos.
- Drill requires the MapR/HPE ODBC driver and KrbServiceHost. Trino requires Simba ODBC; NReco is unsupported.

See [exact driver settings and verification boundaries]({{ '/operating-system-identity-mappings/' | relative_url }}) for CLI/Library examples, platform prerequisites, TLS/role rules, fixture commands and unverified live routes.
